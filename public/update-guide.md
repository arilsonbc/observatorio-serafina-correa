# Atualização automática do Observatório Serafina

O Site deve permanecer privado e exclusivo do proprietário. O endpoint de sincronização depende dessa barreira de acesso. Não publique o endpoint de escrita para visitantes anônimos.

1. Obter `get_site` para este Site e seu token de acesso de serviço. Não salvar, imprimir ou incluir o token em comandos ou argumentos. Usá-lo somente para este Site, no cabeçalho `OAI-Sites-Authorization: Bearer <token>`.
2. Baixar do próprio Site os arquivos `/collector.mjs`, `/municipal.mjs` e `/municipal-ca.pem` para uma pasta temporária. Usar o acesso de serviço para esses downloads e verificar respostas HTTP 200. Estes arquivos fazem parte do código publicado.
3. Executar `node collector.mjs` com Node 22 ou superior e curl disponível. Aguardar a mensagem de entrada oculta; fornecer por stdin um JSON com `site` (origem exata), `token` e `years` (ano corrente e ano anterior). Nunca fornecer a credencial na linha de comando. A coleta inicial consultou 2014 a 2026 e gravou os retornos disponíveis de 2017 a 2026; a fonte retornou HTTP 500 para 2014–2016; a rotina atualiza os dois exercícios recentes. Reprocessamentos de períodos mais antigos podem ser feitos com `years` explícito, ou `jobs` contendo objetos `{kind,year,month}`.
4. O coletor verifica a assinatura do intermediário ZeroSSL usando uma raiz já confiável do Node e sua validade temporal, e usa o conjunto de raízes e esse intermediário para completar a cadeia no curl. A verificação HTTPS permanece ativa. Nunca usar `-k`, `--insecure` ou desativar a verificação TLS. Se a cadeia municipal mudar, informar a falha e revisar o certificado com a autoridade emissora.
5. O coletor consulta a API oficial Fiorilli, fixa Empresa=1 e exclui CPF/dados bancários antes de transmitir os registros normalizados ao `/api/snapshot`. As chaves por tipo/ano/mês substituem a coleta daquele período, sem duplicação. Falhas preservam a última cópia gravada. Não republicar o Site para atualizar dados.
6. Conferir o resumo final: `saved` deve corresponder a `jobs` e `failures` deve estar vazio. Ler `/api/dados?kind=salary&year=ANO&month=MES` e outro período de despesas com o mesmo acesso de serviço e conferir `fetchedAt`/quantidade de registros. Não imprimir nomes ou remunerações no relatório da automação. Informar somente mudanças relevantes, falha, conclusão da primeira execução ou ação necessária; permanecer silencioso quando não houver novidade relevante.

Fontes: https://sistemas.serafinacorrea.rs.gov.br/transparencia/versaoJson/DadosAbertos/ e APIs documentadas. Pagamentos são agregados mensais por CNPJ; folha é por competência, referência de folha e matrícula; contratos são filtrados por assinatura e excluem anulações; licitações são filtradas pela publicação do edital. A API não fornece vencedores. Não transformar contratos em vitórias de licitação.
